4Autonomy Policy

One page, one workflow, day-one level stated (R3)

Problem statement

Pick one workflow (month-end log triage, dependency bumps, or first-response incident summaries). Write one page covering which tasks sit at which autonomy level, the controls that make each level safe, the evidence needed to move a task up a level, and who approves the move. Then state which level the team can run on day one, given two of six engineers are new to the codebase.

What we did

  • Workflow chosen: month-end log triage (both evidence-pack incidents happened at month-end).
  • Levels L0–L3: Manual → Assist (suggest) → Act-with-checkpoint → Act-and-notify. A hard boundary: no level changes production.
  • Controls per level: read-only + mandatory citations at L1; draft-only write surfaces at L2; "advisory, not root cause" banner + kill switch + audit log at L3.
  • Promotion evidence: two scored month-end cycles, grounding integrity, disprovability, tested reversibility.
  • Approvers: tech lead (L0→L1); tech lead + incident commander (L1→L2); both + SOC 2 sign-off (L2→L3); any on-call can demote instantly.
Day-one level: L1 (Assist) everywhere, with one task type piloted as a supervised L2 — because there is no accuracy track record yet and the two newcomers can't yet sanity-check a confident-but-wrong summary.
