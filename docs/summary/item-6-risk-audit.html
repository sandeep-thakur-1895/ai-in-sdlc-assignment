6Risk Audit

Lethal-trifecta audit with a recorded decision (R5.1–R5.2)

Problem statement

Audit the agent setup against the lethal trifecta — private data, untrusted content, external communication — and name which legs are present. Then either redesign to remove one leg or accept the risk in writing with a trigger that would make you revisit.

What we did

Found all three legs present in the triage/review + MCP setup over the planned production service:

Leg 1 — Private data
logs, 7-year audit trail, PayEx API key in prod config.
Leg 2 — Untrusted content
production logs carry injectable fields; Playwright MCP renders arbitrary pages.
Leg 3 — External comms
Playwright browser can hit any URL; no egress restriction.
  • Described the concrete end-to-end injection attack this enables (crafted invoice field → logs → triage agent → browser exfiltrates the PayEx key).
  • Redesigned to sever leg 3: no network-acting tools in the triage agent, egress allowlist, secrets out of agent reach, pinned MCP launch.
  • Accepted the residual (legs 1+2, intrinsic to triage) in writing, with a four-condition revisit trigger.
Recorded decision: break the trifecta by removing leg 3 (external communication); accept legs 1+2 with a revisit trigger that re-arms a full audit if any network-acting tool, widened egress, logged secret, or promotion-to-act appears.
