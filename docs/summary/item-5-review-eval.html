5Review Evaluation

Two added cases + three-run and changed-variable results (R4)

Problem statement

Run the ten fixed cases in ops/evals three times against one review prompt and report caught / missed / false-alarm rates, not anecdotes. Add two cases of your own from real defects, at least one clean. Then change exactly one variable (prompt, model, or context) and run the set again. Say whether it improved and how confident you are at that sample size.

What we did

  • Ran the fixed ten 3× against prompt v1; reported rates (ten-case baseline: 81.0% caught, 19.0% missed, 11.1% false alarm).
  • Added case-11 (defect: .Result sync-over-async blocking) and case-12 (clean: guard-clause extraction).
  • Changed exactly one variable — the prompt (v1→v2), model and context held constant — and re-ran the full set.
  • Verdict: direction positive on every metric, but confidence low — the caught gain is ~3 correlated instances, the false-alarm gain is a single event, and v2 was tuned on the test set.
