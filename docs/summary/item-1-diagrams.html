1As-built & Target Diagrams

Mermaid source + citation list + inferred-items list (R1)

Problem statement

Produce, using the Mermaid MCP, a container view and a sequence diagram of the approval path for the system as it exists today, citing a file or symbol for every element, listing separately everything the agent only inferred, and correcting whatever was wrong. Then draw the target state once Azure SQL persistence and PayEx are in, clearly marking which parts do not exist yet. Constraint: ops/ describes a planned deployment, so the diagrams must follow the code, not ops/.

What we did

  • As-built doc with exactly one Mermaid container diagram and one approval-path sequence diagram, both rendered through the Mermaid MCP with zero syntax errors.
  • Citations (C1–C21): every diagram element mapped to a real file/symbol (e.g. SessionAuthMiddleware.InvokeAsync, ApprovalService.Approve, IInvoiceRepository.Update).
  • Inferred (I1–I5): a separate list of elements the agent inferred (the browser actor, HTTP/Bearer edges, DI relationships, status-code outcomes) — kept apart from citations, with no gaps or overlaps.
  • Corrections: recorded the one real fix — EnsurePending is a private static method, not a public/callable one.
  • Target-state doc: container + sequence diagrams adding Azure SQL, PayEx, and a submission worker/outbox, each marked not-existing-yet via a two-style classDef + legend; the 30s ambiguous-timeout branch shows both outcome paths. Existing components cited to code; planned components never cited.
